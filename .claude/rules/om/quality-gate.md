# OpenManager 품질 게이트 공통 규칙

## 목적

AI Agent가 변경 범위를 통제하고, 실제로 수행한 검증 결과만 정확하게 보고하도록 품질 기준을 정의합니다.

## 변경 전 확인

코드나 설정을 수정하기 전에 다음 내용을 확인합니다.

1. 요청 사항과 완료 조건
2. In Scope
3. Out of Scope
4. Impact Area
5. Protected Area
6. 기존 구현과 재사용 가능 항목
7. 검증 방법

## 변경 원칙

- 필요한 파일만 최소 범위로 수정합니다.
- 요청 범위 밖의 리팩터링을 임의로 수행하지 않습니다.
- 기존 구현을 재사용할 수 있으면 중복 생성하지 않습니다.
- 여러 파일을 변경하면 파일별 변경 이유를 기록합니다.
- 생성 코드나 Vendor 코드는 명시적인 요청 없이 수정하지 않습니다.
- 기존 테스트의 Assertion을 약화하여 억지로 통과시키지 않습니다.

## 검증 원칙

변경 범위에 맞는 검증을 수행합니다.

최소한 다음 항목을 확인합니다.

```bash
git status --short
git diff --check
git diff --stat
```

코드 변경 시에는 해당 영역의 Build, Lint, Type Check, Test 명령을 확인하고 가능한 범위에서 실행합니다.

## 결과 보고 형식

작업 완료 후 다음 순서로 보고합니다.

1. 변경 요약
2. 변경 파일 목록
3. 파일별 변경 목적
4. 실행한 검증 명령
5. 검증 결과
6. 실행하지 못한 검증
7. 남아 있는 위험 요소
8. 사용자 확인이 필요한 사항

실제로 실행하지 않은 검증은 반드시 `미실행`으로 표시합니다.

## 실패 처리

- 실패한 검증 결과를 숨기지 않습니다.
- 실패 원인을 분석하고 영향 범위를 보고합니다.
- 실제 애플리케이션 오류와 테스트 코드 오류를 구분합니다.
- 사용자의 승인 없이 Assertion을 약화하지 않습니다.
